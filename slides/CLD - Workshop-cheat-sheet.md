## 1. Why Amazon OpenSearch Service?

Amazon OpenSearch Service is a managed search and analytics platform based on OpenSearch.

**Example: Swiss SME**

A Swiss e-commerce company operates a web application on AWS. Logs are generated by:
- EC2 instances
- Application servers
- Load balancers
- Security services

Without centralized search, troublshooting failures and monitoring performance becomes difficult.
OpenSearch collects, indexes and analyzes these logs, enabling fast searches, dashboards and alerts.

### Typical Use Cases

- Centralized log management
- Application monitoring
- Security event analysis (SIEM)
- Full-text search
- Operational dashboards
- Alerting

## 3. Benefits and limitations

### Benefits

- **Managed AWS service**
- **Fast full-text search** 
- **Centralized observability**
- **Dashboards and visualization** 
- **AWS integration (CloudWatch, Lambda, Kinesis, S3)** 
- **Scalable architecture** 
- **Security controls and encryption**

### Limitations

- Costs grow with storage and traffic
- Requires cluster sizing and tuning
- Vendor lock-in to AWS
- Long-term archival storage is usually cheaper in S3

## 4. Cost structure

**Amazon OpenSearch Service can be used in two main deployment models: managed clusters and serverless collections.**

### Managed Cluster Pricing

Main cost components:

- Instance hours: the compute instances used by the OpenSearch cluster.
- EBS Storage: EBS volumes used to store indexed data.
- Data transfer: network traffic in and out of the service.
- Snapshots/backups: storage used for backups.
- Optional ingestion pipelines: if OpenSearch Ingestion is used to process and send data into OpenSearch.

### Serverless Pricing

Main cost components:

- OpenSearch Compute Units (OCUs)
- Storage used by indexed data
- Ingestion capacity
- Query capacity

## 5. Getting Started

### Prerequisites

- AWS account
- IAM permissions
- Log source or sample data
- AWS Console or AWS CLI

### Setup steps

1. Open the AWS Console
2. Open Amazon OpenSearch Service
3. Create Domain or Serverless Collection
4. Choose the deployment type:
   - managed cluster for more control
   - serverless collection for simplified capacity management
5. Configure network access:
   - public access for a test environment
   - VPC access for production
6. Configure IAM permissions
7. Create index
8. Send documents
9. Query data
10. Build dashboards

## 6. Hello World
  
  
Create an index:  
  
```bash  
PUT /products
```

Add a document:
```
PUT /products/_doc/1
{
  "name": "Swiss chocolate",
  "category": "food",
  "price": 4.50
}
```

Search:

```
GET /products/_search
{
  "query": {
    "match": {
      "name": "chocolate"
    }
  }
}

```
Result: returns matching documents.

## 7. Common Operations


### Search

```bash
GET /logs/_search
{
  "query": {
    "match_all": {}
  }
}
```

### Time Filter

```bash
GET /logs/_search
{
  "query": {
    "range": {
      "timestamp": {
        "gte": "now-1h",
        "lte": "now"
      }
    }
  }
}
```

### Aggregation

```bash
GET /logs/_search
{
  "size": 0,
  "aggs": {
    "errors_by_service": {
      "terms": {
        "field": "service.keyword"
      }
    }
  }
}
```

## When Should You Use OpenSearch?

Use OpenSearch when you need:

- Fast search across large datasets
- Centralized logging
- Monitoring and observability
- Dashboards and analytics
- Security event analysis

Avoid OpenSearch for:

- Relational transactions
- Banking/accounting systems
- Small datasets that fit in a database
- Long-term archival storage
